    Integrations¶

    sutura connects to two kinds of system. A catalog supplies the definitions: models, joins and metrics. A data system holds the data and runs the queries. Each adapter has one page. Kinds and settings lists the keys that every catalog and every data system reads.

    Catalogs¶

    A catalog serves one governance model. In multi-player governance, many owners keep one reviewed source of truth in a shared catalog: see the multi player example. In single-player governance, one owner keeps the files in the repository: see the single player example.

    • Markdown catalog

      Catalog · single-player governance

      Write the whole model as markdown files and review it in git.

      Markdown catalog

    • DataHub

      Recommended Catalog · multi-player governance

      Read models, joins and certified metrics from a shared DataHub.

      DataHub

    • OKF

      Catalog · single-player governance

      Read table structure and descriptions from Frictionless Table Schema files.

      OKF

    • Data Contract

      Catalog · single-player governance

      Read tables, columns and joins from Open Data Contract Standard v3 documents.

      Data Contract

    • OpenMetadata

      Catalog · multi-player governance

      Read tables, descriptions and joins from a shared OpenMetadata.

      OpenMetadata

    • RDBMS dictionary

      Catalog · multi-player governance

      Read table descriptions from a documentation view in PostgreSQL or Oracle.

      RDBMS dictionary

    • Wren

      Catalog · single-player governance

      Convert a WrenAI manifest into a markdown catalog that you review.

      Wren

    Data systems¶

    A data system runs in one of two identity modes. With shared-service-user, every caller's query runs as the one identity that the deployment declares. With secure-impersonation, each caller's query runs as that caller's own identity at the source.

    • DataFusion (files)

      Data system shared-service-user

      Run questions over Parquet, CSV and NDJSON files, inside the sutura process.

      DataFusion

    • DuckDB

      Data system shared-service-user

      Run questions over one DuckDB database file, opened read-only.

      DuckDB

    • BigQuery

      Recommended Data system shared-service-user secure-impersonation

      Run questions as one service account or as each caller's own account.

      BigQuery

    • PostgreSQL

      Data system shared-service-user

      Run questions over a PostgreSQL database as one declared role.

      PostgreSQL

    • ClickHouse

      Recommended Data system shared-service-user secure-impersonation

      Run questions over a ClickHouse server through its HTTP interface.

      ClickHouse

    • Oracle

      Data system shared-service-user

      Run questions over an Oracle Database as one declared user.

      Oracle

    Identity mode of each data system¶

    Data system Identity mode
    DataFusion (files) shared-service-user only
    DuckDB shared-service-user only
    BigQuery shared-service-user and secure-impersonation
    PostgreSQL shared-service-user only
    ClickHouse shared-service-user and secure-impersonation (EXECUTE AS)
    Oracle shared-service-user only
