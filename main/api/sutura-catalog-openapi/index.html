    sutura-catalog-openapi¶

    The public API of sutura-catalog-openapi, rendered from rustdoc JSON.

    EXPERIMENTAL. A SemanticCatalog over any HTTP metadata API an OpenAPI 3.0 or 3.1 document describes, read as a declaring source - github.com/telekom/sutura#1727.

    The API is configured, not coded: a pinned copy of its OpenAPI document and a data-only mapping file together name the GET operations that list the models (and, optionally, each model's outgoing links), and where in each answer a name, a description, a column, a key or a link sits, as JSON Pointers. Contract::parse checks the mapping against the document once, before any request; ContractError names each way the two can disagree.

    What it reads, and how far that is proven¶

    Proven against recorded fixtures only (src/fixture/): no live API is part of any check. The models, their columns, the source's own column type word, descriptions, primary keys and many-to-one joins onto a target's single-column primary key. Nothing else: no metric, grain, required filter, allowlist, anchor or knowledge, because the vocabulary has no word for them. docs/what-an-openapi-catalog-can-carry.md is the field-by-field finding.

    What keeps the requests on the declared endpoint¶

    The adapter builds every request target itself (Target): a document path made only of unreserved segments and whole-segment parameters, the mapping's fixed parameters (parsed path segments), each model's own name (parsed by ModelName::parse, whose grammar cannot hold /, ., ?, # or %) and a percent-encoded query. The document's servers and every non-local $ref are never followed, and the only paging style is a cursor sent back as a query value, so no answer can name a URL to dial.

    Limits¶

    • The catalog is read as the deployment: every caller sees what the deployment's token sees.
    • OpenAPI 3.0 and 3.1 only, as JSON; a Swagger 2.0 document is refused by name.
    • A link with no foreign-key column on this side (a to-many side) is not carried.

    Module fixture¶

    The recorded fixtures and the fake reader that serves them.

    fixture/example/ is a synthetic metadata registry: its document, its mapping and the answers it gives, keyed by request target. Written for this adapter, not recorded from a running service. fixture/foundry-sample/ is a sample of the configured mode for one vendor's ontology API: a document subset transcribed from public reference pages and a mapping over it, with no answers.
