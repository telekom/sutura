    sutura-exec-clickhouse¶

    The public API of sutura-exec-clickhouse, rendered from rustdoc JSON.

    A Warehouse adapter over ClickHouse, through its vendored ADBC driver: adbc::AdbcClickHouseWarehouse.

    A shared-service-user source runs every statement as the deployment's declared user. An impersonation-at-source source runs each one as the ClickHouse user named by the asking caller's verified subject: through EXECUTE AS on the deployment's sign-in (see execute_as), or - when the source declares a delegation - signed in as that user with the token the caller's verified assertion was exchanged for. ClickHouse hands that token to the operator's checker.

    One transport, and what holds it¶

    adbc is the only transport: the one sutura serve composes, the one the golden matrix opens, and the one the fixture loader ingests through. What a SERVER answers is held by the executed cells - the golden matrix in sutura-app's tests and this crate's own tests/ load the example corpus into the server nix/clickhouse-tier.nix starts (through fixture, behind the default-off fixtures feature) and pin the rows, refusals, error and anchor report it answers - in checks.nextest and under just test.

    Parameters travel as ClickHouse's own named parameters, never as text¶

    The adapter rewrites each rendered ? into {pN:Type} and binds the value through the driver, which sends it as a separate parameter the SERVER binds by the declared type - see adbc::rewrite_placeholders for why counting ? occurrences against the bound values is safe rather than a guess.

    Deadline, and what was checked about it - see deadline's own header¶

    Every statement sends max_execution_time, computed from what the port's sutura_domain::warehouse::deadline::Deadline has left. deadline's module header states what was measured about that setting's semantics and its limit, mirroring sutura_exec_postgres::deadline's own record for SET LOCAL statement_timeout.

    Every connection and every answering statement pin the server settings sutura needs¶

    Each is a driver option on the connection and a setting in the statement's own SETTINGS clause; under EXECUTE AS only the clause holds - see settings, which also states what the pin does not cover: the fixture loader's statements, and every setting sutura does not pin.

    join_use_nulls=1: under ClickHouse's default 0, the unmatched side of an outer join answers the column type's default - '' for a String - where the SQL standard answers NULL. Measured by hand against the pinned compose server over the example corpus: 6 of the 23 questions with a committed @duckdb row golden disagreed without it, 0 with it, under a non-Nullable schema; under Nullable columns the setting changes nothing, so a fixture importer's type choice decides whether the defect shows - fixture declares no matrix column Nullable for that reason. output_format_json_quote_denormals=1: under the default 0 an infinite float answers the JSON null. timeout_overflow_mode=throw: throw answers a spent max_execution_time with Code 159; break answers HTTP 200 with the rows read so far. The executed goldens hold what the first two settings make the server answer, and nothing executed holds the third. Offline, a loopback cell in tests/adbc_execute_as.rs holds that the statement carries the clause; what the server does with a dropped setting needs the tier.

    What is NOT here¶

    Shipped in every release binary since github.com/telekom/sutura#1237. sutura-cli opens a kind: clickhouse source behind its default-off clickhouse feature, which nix/shipped.nix now enables, once the github.com/telekom/sutura#955 join-nulls fix landed.

    No raw-SQL tool support (Warehouse::ACCEPTS_RAW_STATEMENTS stays at its false default).

    No dry_run override. The ADBC driver has no cheap "prepare, do not run" step this adapter could ask for without paying most of the cost of running the statement, so this stays at the port's own default (Ok(PreFlight::NotAsked)) - the same honest absence Warehouse::dry_run's own doc names for an adapter where checking is not cheaper than running.

    Module adbc¶

    The ClickHouse ADBC transport, the only one this adapter has.

    The driver is the vendored, linked-or-mounted archive prepared by #1571. This module keeps the request identity and channel options on one per-call connection, then hands the driver's Arrow stream straight to Accumulating.

    An impersonation-at-source caller presented as a principal is run through EXECUTE AS on the deployment's own sign-in; a caller presented with an exchanged token signs in with that token instead.

    Module execute_as¶

    Per-caller execution: each statement is sent as EXECUTE AS "<user>" <statement>.

    The per-statement form only. ClickHouse also has EXECUTE AS <user> with no statement, which switches the user for the rest of a session. This adapter never renders it: ClickHouseUser::execute_as is the one place the keyword is written, and it always carries the statement. Each request is also stateless - the ADBC path opens a connection per statement, under a session id the driver draws for it - so no switch can outlive the request that asked for it, and two callers cannot inherit each other's user.

    The user is the caller's verified subject, never caller text. Leg 1 verified the token that carries it, the broker presents it, and it is parsed here to a closed character set and quoted with the dialect's identifier quote. The character set has no quote, backslash or whitespace, so the quoted span cannot be closed early.

    The server half is operator settings this adapter cannot set: the server setting access_control_improvements.allow_impersonate_user = 1, a ClickHouse user named by each caller's verified subject, and GRANT IMPERSONATE ON <user> to the service user. There is no list of callers to check at boot, so a missing user or grant refuses that caller's question at the server - never an answer as the service user. Not available on ClickHouse Cloud.

    Module fixture¶

    The fixture tier: its credential, a private database per open, and a corpus CSV as a table.

    Behind the default-off fixtures feature, like sutura_exec_postgres::fixture, and for its reason: nothing here belongs in a composition root, and --all-features compiles, lints and tests it on every run.

    The loader runs over the transport the adapter ships¶

    A table is created with a statement through the ADBC driver and its rows travel through the driver's bulk ingest as one Arrow batch, so a fixture is loaded by the same transport a served source reads it back with. The CSV is parsed here, under the types csv::infer classified, and the server converts the batch's Arrow types into the declared ones.

    The credential is configured or refused by name¶

    nix/clickhouse-tier.nix generates a password per start and prints the two exports from sutura-clickhouse-tier credentials; nix/with-tier.sh and checks.nextest evaluate them where they export SUTURA_DEV_REQUIRE_TIER. Nothing here defaults a value - the shape sutura_exec_postgres::fixture records the defect of - so an unset or blank variable is a UnconfiguredFixture naming it.

    Column types: the golden matrix's, not the conformance path's¶

    sutura_domain::warehouse::csv::infer classifies each column. Its Decimal is attached as Float64 HERE, deliberately: the matrix's other adapters attach a fractional column as a double (DuckDB's read_csv_auto, sutura_exec_postgres's load_csv, the engine's Arrow inference), so a Decimal column here would answer the same question as text rather than as a real and differ from all three for a reason that is the importer's, not the server's.

    No column is Nullable, and an empty cell is refused. The JOIN_USE_NULLS setting in adbc is measured to matter only over a non-Nullable schema, so a nullable importer would make the executed goldens blind to that setting. And a non-Nullable column reads an empty cell as the type's default - 0, '' - where every other adapter reads NULL: a silently different fixture. No golden-matrix fixture has one; a future one is refused rather than rewritten.

    The federated corpus holds one absent key on purpose, so AdbcClickHouseWarehouse::load_federated_csv declares Nullable exactly the columns holding an empty cell, at the matrix's type, and every other column as the matrix does.

    A blank line is refused, whichever load reads it. csv::infer skips one, and a server reading the file as text refused it; the batch is built here, so the refusal is too.

    Module tls¶

    The TLS material a TLS clickhouse source channel hands the ADBC driver.

    This is the TLS half of sutura_config::sources::transport, turned into the driver's PEM options: configuration owns the three-state DECLARATION (plaintext / verified / mutual), and this module owns reading a declared verified or mutual channel's material. The declared-trust-store rule extends rather than forks (the architecture decision): a PEM bundle or the host's system store, validated once by adbc_options and never a fallback, exactly as the Postgres source channel reads it.

    The read itself lives in sutura-tls, shared with the Postgres source channel and the BigQuery wire so the refusals for an unreadable, empty or malformed bundle/identity are not a third hand-written copy. What is this crate's own is handing the validated bytes on as the PEM text the driver builds its TLS configuration from.

    Why this is a fallible step SEPARATE from opening the adapter¶

    TlsError is its own type rather than a variant folded into crate::adbc::AdbcError: nothing about it can arrive from Warehouse::execute, only from whoever resolves a declared channel before opening the adapter.
